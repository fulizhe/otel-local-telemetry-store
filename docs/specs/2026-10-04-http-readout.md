## Problem Statement

数据已经真的存在应用进程里了（Phase 4b 端到端已验收：`offered = drained = stored` 三者相等、
`metricPoints=7`、`resources=1`、零丢弃零错误），但**没有一个能给人看的出口**。

唯一的出口是 JMX，而它对使用者极不友好：

- **属性只能是 `String` / `int`** —— 因为跨 ClassLoader 传自定义类型必然 `NoClassDefFoundError`，
  所以嵌套结构必须预先摊平成一行文本。
- **查询靠逐个具名方法**（`summary` / `recentSpans(10)` / `spansOfTrace(...)` / `spanPayloadHex(...)`），
  没有筛选、没有排序、不能组合。
- **浏览器完全看不了** —— 而"数据不出机器，但看得见"是这个产品的价值主张，
  "看得见"目前只对会用 `jconsole` 的人成立。

结果是：想确认"这个进程现在收到了什么"，你得先装 `jconsole`、找到那个 MBean、逐个方法点，
而且**载荷只有一串 hex** —— 你看不出那条 span 到底带了哪些 attributes、哪些 events。

## Solution

补一个 **HTTP 读口**：一个端口、一份封闭端点清单、手写 JSON 编码，
外加一个不依赖任何工具的静态只读页面。对外的表面在 ADR-6 里一次定死，实现按它的顺序推进。

关键取舍（详见 Implementation Decisions）：

- **只开一个端口**，JMX 保持零端口且**不开 JMX remote**（默认无鉴权，而载荷装着 SQL 与日志原文）
- 端口冲突退随机 + **实际端口写进 `<dataDir>/otelstore.port` 与启动日志**
- **七个端点、只注册 GET/HEAD**，没有任意表查询、没有载荷下载口 —— 清单封闭是
  "永远不提供 raw SQL"这条原则的执行手段。清单原本是八个，`/api/self` 在实现前被取消（见第七节）
- **JSON 手写编码器**，不引序列化框架
- **自监控指标不入库、也不过缓冲** —— 过滤保留，但被过滤掉的只计数；
  扩展自身健康由 `/api/summary` 在请求时现读。**要"当前状态"从来不需要缓存**
- **页面能看扩展自己的近期日志**（扩展写自己的文件，不读应用的日志）

## User Stories

**运维 / 排障者（主要读者）**

1. 作为排查"这个进程在收什么"的人，我想打开一个网址就看到各类信号的行数与丢弃计数，
   以便**不必装 `jconsole` 就能确认扩展是否在正常工作**。
2. 作为排查者，我想看到队列的 `offered / drained / dropped / sinkErrors / backlog`，
   以便区分"没收到"、"收到了但丢了"、"存库失败"这三种完全不同的情况。
3. 作为排查者，我想看到两个环形文件的**写游标、已覆盖轮次、最老存活 id**，
   以便判断"载荷是不是已经过期"还是"写指针卡住了"。
4. 作为排查者，我想看到**行数水位与已淘汰行数**，以便知道容量水位是不是设得太小。
5. 作为排查者，我想在页面上看到**扩展自己近期的 WARN**（降级、限速告警、编码失败），
   以便不必去翻应用的日志文件。
6. 作为排查者，我想按 **trace_id 取回整个 trace 的全部 span**（按开始时间排序），
   以便看清一次请求的调用链结构。
7. 作为排查者，我想看到单条 span 的 **attributes / events / status**，
   以便知道它到底记了什么，而不用去解一串 hex。
8. 作为排查者，我想看到**最近若干条日志记录**的正文预览、severity 与时间，
   以便把日志和它所属的 trace 对上。
9. 作为排查者，我想看到**某个指标名最近的数据点**（含桶边界、分位数、属性组合的哈希），
   以便确认指标是不是按预期在增长。
10. 作为排查者，我想在**页面上一眼看到扩展自己的采集与落盘状况**（三条队列的
    offered/drained/dropped/sinkErrors/backlog、行数水位、已淘汰数、自监控指标被丢弃了多少个），
    以便回答"是业务没产生数据，还是 SDK 那边就丢了"。
    > 原稿写的是"看到 SDK 自监控指标（agent 自己的 `processedSpans` 等）"。
    > 2026-10-05 实测发现那批指标在 agent 2.32.0 上默认根本不会到达（见第七节），
    > 所以改为"扩展自己的队列与水位"——**它回答的是同一个问题，而且一定拿得到**。
11. 作为排查者，我想看到**生效配置**（限额、水位、队列容量）与**启动时间、实际端口**，
    以便确认拿到手的配置就是生效的那一份，并判断"这是不是同一个进程的数据"。

**应用开发者**

12. 作为应用开发者，我想在浏览器里按 30 秒自动刷新看最新计数，
    以便**不动本地文件、不重启进程**就观察到数据在进来。
13. 作为应用开发者，我想看到自己造的那批 span 在库里的样子（名字、trace、耗时、状态），
    以便确认埋点是对的。
14. 作为应用开发者，我想确认"应用打出去的日志和它所属的 span 是关联的"，
    以便排查时能把两件事串起来。

**SRE / Prometheus 使用者**

15. 作为抓取器使用者，我想有一个 **`/metrics` Prometheus 文本端点**，
    以便把它加进 scrape 配置就完事，不需要写适配器。
16. 作为抓取器使用者，我想**默认就能直接抓**（不配 token），以便加一行 scrape 配置就完事；`n    需要收紧时我再显式打开 token。
17. 作为抓取器使用者，我想看到**每个指标每个属性组合的当前值**，
    以便画图；而不是只看到一个自增的行数。
18. 作为抓取器使用者，我想让**直方图的桶边界与分位数正确还原**，
    以便 `histogram_quantile` 算出来的分位数是对的。

**脚本 / 自动化**

19. 作为脚本使用者，我想 `curl` 直接就能读到 JSON（默认无鉴权），
    以便把它塞进巡检脚本；配了鉴权时才需要自己加一个头。
20. 作为脚本使用者，我想拿到**结构化 JSON 而不是只能给人看的文本**，
    以便用 `jq` 之类的工具处理。
21. 作为脚本使用者，我想在**参数非法时拿到明确的 HTTP 状态码与错误 JSON**，
    以便脚本能区分"没数据"和"请求写错了"。
22. 作为脚本使用者，我想让**响应里永远不含 token**，
    以便日志与抓包都不会泄露访问凭据。

**安全与隐私关注者**

23. 作为安全关注者，我想让**默认绑定 `0.0.0.0`** 以便从别的机器就能看，
    同时知道默认**没有**鉴权、风险具体是什么、以及怎么一步收紧。
24. 作为安全关注者，我想**用完能立刻关掉**（`auth=true` 收紧，或干脆把 `host` 收到 `127.0.0.1`），
    以便在受管环境里不留暴露面。
25. 作为安全关注者，我想确认**资源属性白名单在读口侧也生效**，
    以便命令行、token、口令不会出现在页面上。
26. 作为安全关注者，我想确认读口**不提供任何写操作，也不提供任意 SQL**，
    以便"只读"是结构性保证而不是口头承诺。
27. 作为安全关注者，我想确认**不读应用的日志文件**，
    以便这个扩展不会把业务日志内容复制到一个新的暴露面上。

**运维配置场景**

28. 作为运维，我想要**端口冲突自动退让**且应用照常启动，
    以便端口占用不会变成一次故障。
29. 作为运维，我想要**从文件或日志里找到实际端口**，
    以便不必去猜、去扫端口。
30. 作为运维，我想要在**有多个实例指向同一个数据目录**时得到明确警告，
    以便避免读到别的进程的数据（ADR-4 声明的场景）。

**长期维护者**

31. 作为维护者，我想让**端点清单封闭**、加端点要走决策记录，
    以便"口径 proliferation"这类最常见的存储错误被流程挡住。
32. 作为维护者，我想让读口**不引入任何三方依赖**，
    以便不必为了一次 JSON 再背一遍 relocation 与字节码核对的负担。
33. 作为维护者，我想让**载荷解码只有一层**，
    以便将来换一套编码时改动面收敛在一处。

## Implementation Decisions

**范围与顺序**（沿用 ADR-6 末尾给出的顺序，每段可独立验收）

1. 端口
2. `/api/summary`
3. `/metrics`（Prometheus 文本）
4. 列表端点（traces / logs / metrics）
5. 载荷解码
6. `/api/self-log`
7. `/` 静态页面

**一、端口**

- 只开一个端口，且只有 HTTP 有。JMX 走进程内平台 MBeanServer，**零端口**；
  **不开 JMX remote**（RMI/JMXMP）—— 它默认无鉴权，而载荷装着 SQL 语句、HTTP header
  与日志原文；它还是应用的 JVM 参数，不该由我们替用户决定。
- 先试配置值（默认 17890），`BindException` 则退到随机端口。
- **实际端口写进 `<dataDir>/otelstore.port`，每次启动覆盖写** —— 进程崩了没关的话，
  残留文件会报一个错的端口，这比没有文件更坏。
- 同时打一行日志（文件给程序读，日志给人看）。
- **端口配置不允许填 0**：绑定 0 让 OS 挑确实省事，但用户没法预先在防火墙上开口子。

**二、端点清单（封闭清单）**

- `/` 纯静态只读页面，无框架无构建，30 秒自动刷新，**不含任何数据**。
- `/api/summary`、`/api/traces`、`/api/logs`、`/api/metrics`、`/api/self-log`、`/metrics`。
- **只注册 GET/HEAD**，连 OPTIONS 都不注册。
- **没有"任意表 + 任意条件"的通用查询，也没有原始载荷下载口。**
  每个查询都是一个具名端点：口径写在路径与参数名里，同时守住"永远不提供 raw SQL"。
- `limit` 的上限**按用途分档**：列表 200、日志尾部 500、**指标点 2000**；缺省一律 20（日志尾部 100）。
  指标那条抬到 2000 是因为它是**看趋势**的（最近半小时 × 每秒一点 = 1800 条），
  不是"多给数据"—— 上限的意义是"别让读口变成导出工具"，不是"越少越好"。

**三、鉴权：默认不要求 token**

- **默认一律不要求 token**（2026-10-04 决定，与初版相反）。理由与代价见 ADR-1：
  这个扩展的定位是"挂在本机应用里自查"，默认要 token 会给最常见的用法加一道
  "去文件里复制 token 粘进页面"的工序，而那道工序挡不住真实威胁。
- `auth=true` 时才启用：
  - `/api/*` 与 `/metrics` 要求 token，放在 `X-Otel-Store-Token` 头里 ——
    **不用 query 参数**，它会进浏览器历史与 access log。
  - Prometheus 侧对应 `authorization.credentials_file`。
  - `/` 页面出现一个"粘贴 token"输入框，值存 `sessionStorage`（关标签页即失效），
    由页面里的 JS 带上那个头。
    URL 带 `?token=` 会落进浏览器历史；`Set-Cookie` 会让 token 进入之后每个请求 ——
    两条都否决，这是唯一同时满足"不进 URL、不进 cookie、浏览器能自动刷新"的做法。
  - token 仍每进程随机、写 `<dataDir>/*.token` 与启动日志，
    **绝不进入任何响应体、日志或异常消息**。
- **无鉴权且绑定地址不是回环时，必须在启动日志里打一条显著警告**：
  说明任何人都能读全部载荷、以及配 `auth=true` 的方法。
  默认 `host=0.0.0.0`，所以这条警告**默认就会打** ——
  这是"默认方便"这个选择的必然成本，把它藏起来才是真的危险。

**四、跨源**

- **浏览器直接打开读口那侧**，因此**不开 CORS**、demo-app 不加代理、不加任何本地转发。
- 代价：那个页面不在 demo-app 的导航里，要另开一个标签页。
- ADR-1 与验证笔记里悬着的"读口跨源取舍"到此关闭。

**五、返回形态**

- **手写 JSON 编码器**，只支持 Map / List / String / Number / Boolean / null ——
  我们输出的一切形状都是自己造的。
- **不支持任意 POJO 反射**：将来有人想输出自定义对象时，编码器**抛错**而不是静默输出 `{}`。
- 不引 Jackson / Gson：省下约一百行，代价是 relocation、版本选择、
  以及"字节码必须 52"这条约束再核一遍。
- 错误统一形态：HTTP 状态码 + 一个 `error` / `kind` 字段，**不含栈**（栈进扩展自己的日志）。
- **Prometheus 端点不走 JSON**，是另一种文本格式（另一只手写的小渲染器）。
- 必须处理的 JSON 陷阱：控制字符与引号反斜杠的转义、非 ASCII 的处理、
  以及 **`NaN` / `Infinity` 不是合法 JSON**（标量形态的指标值会出现）。

**六、载荷解码**

- 读口需要把载荷里的 attributes / events / status 显示出来，所以要解码 protobuf。
- 解码逻辑单独一层，**只依赖 shade 之后的 proto 类**，
  **不 import 任何 `io.opentelemetry.*`** —— 因此不破坏 ADR-1 的分层，
  而且它是将来"换一套编码"时唯一的改动点。
- **不做原始载荷下载口**：hex 形态留在 JMX 里就够排障。
- 体积天然有界：单条载荷受 `max.payload.bytes` 封顶，批量由 `limit` 封顶。

**七、自监控指标：只计数，不缓冲**

> **本节已被实测推翻并重写，以 [ADR-6 第八节](https://github.com/fulizhe/otel-local-telemetry-store/blob/main/docs/adr/adr-06-readout-http-surface.md) 为准。**
>
> 原设计假定"数据已经在管线里、只是被过滤掉了"，于是配一个 200 点的进程内缓冲加一个 `/api/self` 端点。
> 2026-10-05 实测（agent 2.32.0）发现被过滤的那批**默认配置下根本不会到达**
> —— 315 份仪表化清单里只有 `runtime-telemetry` 对得上，而它是 `2.32.0-alpha` 且默认关。
> 为一份不存在的输入建缓存，还多养一个永远返回空数组的端点，所以两者都被取消。当前形态：

- 前缀过滤**保留**（含在 agent 2.32.0 里查无对应模块的那 4 个），自监控指标**仍然不入库**。
- **不引入任何缓冲**，被过滤掉的批次**只计数** → `/api/summary` 的 `selfTelemetryDropped`。
- **扩展自身健康一律请求时现读**（全是已有计数器）—— 要"当前状态"从来不需要缓存，
  缓存只是为了要"历史"。
- **`/api/self` 取消** —— 它只会是 `/api/summary` 的重复。
  取消后 `/api/summary` 是唯一自监控面，为此**平铺**补 5 个键：
  `actualPort` / `startedAt` / `uptimeMs` / `agentVersion` / `storeDegradedReason`。
  其中 `actualPort` 与 `config.port` 不是重复信息：后者是配置值，前者是冲突退随机后的真实端口。
- **业务指标的历史归业务层缓冲**：业务层每秒发一个点，我们像收任何业务指标一样收下，
  走的是已验收过的现成路径。
- 代价：想要自监控指标的**历史**，得自己开 runtime-telemetry 并接一个 `MetricReader`。我们不再提供这个便利。

**八、扩展自己的日志**

- 扩展自己的日志由 **`SelfLog` 门面**写 `<dataDir>/otelstore.log`、备份
  `<dataDir>/otelstore.log.1`，**单文件 1 MiB、只留 1 份备份** —— 符合本项目"有界"的第一原则。
  各处日志改调 `SelfLog.info/warn`（写文件 + 照常走 JUL）。**不是给 logger 挂 Handler**：
  实测 agent 把 `java.util.logging.Logger` 换成了 `PatchLogger`，`addHandler` / `setLevel`
  都是空操作，挂 Handler 收不到记录（理由见
  [ADR-6 第九节](../adr/adr-06-readout-http-surface.md)）
- `/api/self-log` 读它的**尾部 N 行**（默认 100、上限 500）。
- **只读这个文件，不读应用的日志、也不猜 stderr 去了哪**：
  stderr 落哪个文件由启动方决定，扩展无从得知；为了展示自己的状态去读别人的日志文件
  等于伸手到不该碰的地方，还会把应用日志内容复制到读口页面上，直接扩大 token 的泄露面。
- 编码跟随平台。同进程内读写永远一致，读口接口不受影响；
  把文件拷到另一台机器看可能乱码 —— 那是运维自己制造的问题，不是接口的缺陷。
- 零三方依赖（handler 是 JDK 的）。

**九、模块边界**

- HTTP 服务器、路由、鉴权、JSON 与 Prometheus 渲染、载荷解码 —— 全部在 `readout`，
  且 `readout` **仍然只读**（本次不给它加任何修改接口）。
- 端口文件（`.port`，以及启用鉴权时的 `.token`）的落盘由读口负责，但数据目录的**路径**来自配置。
- 不给 `readout` 增加对存储写路径的任何引用。

## Testing Decisions

**什么算好测试**：只测外部可观察行为，不断言实现细节。
不测"JSON 编码器内部有几个方法"、"路由表有几条"这类会随重构变的东西；
测的是"给定这个请求，返回这段 JSON"、"绑定被占时，实际端口落在这个文件里"。

**主缝：真实 socket 上的 HTTP** —— 读口起在 `127.0.0.1:0`，用 `HttpURLConnection` 真发请求。
一处覆盖：路由、`limit` 上限、端口冲突退随机、`*.port` 文件内容、鉴权开启时的拒绝路径、
每个端点的 JSON 形状、错误形状。

**辅缝：四个纯函数**（契约精确、边界容易写错，值得各自单测）

1. **JSON 编码器**：转义（引号 / 反斜杠 / 控制字符 / 非 ASCII）、空容器、`null`、
   嵌套、`NaN` 与 `Infinity` 的处理、数字格式。
2. **Prometheus 渲染器**：标签值转义、`_bucket{le=…}` 的形态、
   `_sum` / `_count`、同名多属性组合的并列。
3. **OTLP 载荷解码**：给定编码出的 bytes → 得到 attributes / events / status；
   空载荷、损坏载荷、字段缺失的降级。
4. **扩展日志尾部读取**：写入若干行后读尾部 N 行；行数超过上限时的截断行为。

**复用现成缝**（不新造）

- 存储层的读 API —— 已有测试覆盖，本 spec **不改它的行为**。
- 组合根 —— 已有"SDK 造真实对象 → 管线 → 存储"的集成测试先例，
  自监控旁路的测试沿用同一套路：喂进去带自监控 scope 的指标，断言**不在存储里、
  但在旁路快照里**。
- 端口发现与 token 落盘 —— 走主缝（真 socket），不单独建缝：
  这两处只有真绑定一次才算验过。

**合计 6 个测试类**（1 个主缝 + 4 个纯函数 + 1 个旁路行为）。

**进程内测试的已知局限**（必须写进测试的注释里）：进程内全绿**不等于**挂 agent 时能跑。
Phase 4b 已经踩过两次这种坑（一个靠上下文 ClassLoader、一个靠 ClassLoader 委托顺序）。
因此读口做完之后，**验收仍然必须真挂一次 agent**，而验收信号是那条周期汇总行
（关停钩子靠不住：`Stop-Process` 不执行 shutdown hook）。

## Out of Scope

- **HTTP 读口的写操作**：不注册 POST / PUT / DELETE / OPTIONS。只读是结构性保证。
- **任意 SQL / 任意表查询端点**：永远不提供。
- **原始载荷下载端点**：hex 形态留在 JMX。
- **JMX remote 端口**：不开。
- **CORS**：不开；demo-app 不加代理、不加本地转发。
- **分页游标 / 排序参数**：v1 的查询都是"看一眼"，有上限即可。
- **流式响应 / SSE / WebSocket**：不做。
- **数据库落盘的表头**（ADR-4 已定，随进程存活、重启清空）。
- **metrics 的分钟 / 小时 rollup**：仍只定义"时间序列形态 + 行数水位"。
- **多实例支持**：明确不支持，遇到要先写决策记录。
- **把自监控指标写进存储**：那条原则不动。
- **读应用的日志文件**：只读扩展自己写的那一个。
- **引 Jackson / Gson 或任何序列化框架**。

## Further Notes

- **ADR-6 是本 spec 的授权依据**。若实现过程中发现它哪一条不成立，
  **先改决策记录，再改代码** —— 不要偷偷绕过。
- **鉴权默认关闭**是这一版最重要的姿态变化，实现时不要"顺手"打开。
- **token 的传递方式选 header 而不是 query**，是为了不进浏览器历史与 access log；
  代价是"从命令行 curl 读口"要自己带一个头 —— 而这只在配了鉴权时才存在。
- **实现顺序里每一段都能独立验收**，不必等全部写完。`/api/summary` 那一段尤其值得先做 ——
  它同时验证端口退随机、`*.port` 文件、默认无鉴权这三样**目前还没有任何代码证明**的决定。
- **不要在实现完成前把端点表写进 README**。本项目已经吃过一次亏：
  文档写着"骨架阶段"而代码已经落地（那次是往回改，这次要一开始就别往前写）。
- 端口发现只解决了"怎么找到它"。**没解决**"两个实例指向同一个数据目录"——
  那是 ADR-4 声明不支持的场景，本次不处理，但页面上应当让人能看出这一点
  （例如显示启动时间与端口，便于判断是不是同一份数据）。
