扩展自身

–
自监控指标（agent 自己的那批）不入库，也不过缓冲 —— 被前缀过滤掉的只计数。
理由：2026-10-05 实测 agent 2.32.0，那批数据默认配置下根本不会到达 （315 份仪表化清单里只有 runtime-telemetry 对得上，而它是 2.32.0-alpha 且默认关）。为一个不会到达的数据建缓存没有意义。
所以这一页没有一个"自监控指标"图表，而是有下面那张队列表 —— 它回答的是同一个问题（"是业务没产生数据，还是采集/落盘这一段就丢了"）， 而且一定拿得到。详见 docs/adr/adr-06-readout-http-surface.md 第八节。
业务指标的历史不归我们：想要"最近半小时"的曲线， 业务层要自己每秒发一个点，我们照常像收任何业务指标一样收下、只存不缓存。
扩展自己的日志在下面那张卡片里（端点 /api/self-log）， 排障时不用再去翻应用的标准错误。

扩展自己的日志

加载中…
–
只读扩展自己写的那一个文件 <dataDir>/otelstore.log （单文件 1 MiB、轮转 1 份，备份是 otelstore.log.1）。尾部默认 100 行、最多 500 行。
不读应用的日志文件、也不猜 stderr 去了哪：那是别人的文件， 为了展示扩展自己的状态去读它，等于把应用日志内容也复制到这一页上。

生效配置

加载中…
–
命名空间是 otel.localstore.*，避开 OTel 自己的 otel.traces.* / otel.metrics.* / otel.logs.*。
配置永不失败：非法取值回落默认值、不抛异常（见 LocalStoreConfig）。 所以这里显示的永远是一份能跑的配置 —— 想知道自己写错了什么， 要对源码里的默认值，不是看这一页。
